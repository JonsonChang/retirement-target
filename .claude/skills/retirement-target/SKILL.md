# 退休金目標試算

**原則：網路上查得到的資料不問使用者。** 只問個人現況，其餘自己查。

所有計算都用**實質**（今天的購買力）進行，名目報酬以費雪方程式換算：$1+r_{real} = (1+r_{nom})/(1+i)$。

檔案：
- `scripts/fetch_market.py`：抓各標的近 10 年月報酬，算波動率、相關係數、匯率
- `scripts/calc.py`：確定性公式 + 蒙地卡羅。`--report` 產生計算底稿（只有數據與算式，第 0～12 節：關鍵數字總表、輸入與假設、達標標準總對照表、固定收入與一次領（含空窗期）、退休時配置轉換、各年齡退休試算（燈號、不足／餘裕、25 倍是否達標）、情境敏感度（生活費 ±10%、每月投入歸零／+50%、股票報酬 −0.5%、退休 ±2 年）、跨越點、25 倍法則與資產重組（安全池、兩池 vs 每年再平衡）、蒙地卡羅數據、計算過程（公式、代入值與逐年明細）、資料來源、假設與限制），圖表為 Mermaid `xychart-beta`；`--json` 另存同一份數據的結構化數據檔（含各表與圖表資料），給步驟 4 的 subagent 取數字用
- `reference/input_schema.md`：`calc.py` 的輸入格式（**組 JSON 前必讀**）
- `reference/defaults.md`：資產類別預設值、勞保勞退規則、通膨與餘命的退路（**查資料前必讀**）
- `reference/final_report_guide.md`：最終報告的改寫指引（步驟 4 交給 subagent 讀）

以下 `$SKILL` 代表本 skill 目錄 `.claude/skills/retirement-target`。

## 步驟 1：問使用者（一次問完，已提供的不要再問）

必填：
- 目前年齡、性別、出生年（用來查勞保法定請領年齡）
- 預計退休年齡
- 退休後每月生活費（**以今天的物價**）
- 持股清單：代號 + 市值（或股數，由你用抓到的價格換算市值）
- 現金／定存金額
- 每月可投入金額
- **退休後的資產配置**：給選項讓使用者挑，例如「股 40／債 60（建議）」「股 60／債 40」「維持目前配置」，也可以自訂標的與比例。選股債比例時，股票部分沿用目前持有的股票類標的比例，債券用 BND
- **勞保領取方式**：月領年金，或是一次領後存入投資組合。一次請領老年給付只有 98 年（2009）前就有勞保年資的人可以選；98 年後才加保且年資滿 15 年的人只能月領；年資未滿 15 年只能一次領（老年一次金）。請使用者看勞保年資的「首筆資料」加保日期來判斷
- **勞退領取方式**：月領，或是一次領後存入投資組合（勞退年資未滿 15 年只能一次領）

選填（不知道可以跳過）：
- 勞保：平均月投保薪資（最高 45,800）、預計總年資、打算幾歲請領
- 勞退：個人專戶目前餘額、月提繳工資、有沒有自提
- 其他退休後固定收入（租金、年金險……），以及起訖年齡；一次性收入（儲蓄險到期領回、出售資產等）的金額與領取年齡

## 步驟 2：自動取得資料

**先查本機快取，沒有或過期才上網。** 快取放在專案目錄（`$SKILL` 往上三層）的 `.cache/retirement-target/`，已加入 `.gitignore`：
- `market/`：`fetch_market.py` 自動管理，同一個月內重跑直接讀快取（當月未收盤的資料本來就不用）；匯率當天有效。使用者要求最新資料時加 `--refresh`
- `web_lookups.json`：下面第 1、3～6 項 WebSearch 查到的數值。查之前先讀這個檔，找到對應的 key 且 `expires` 晚於今天就直接用（`sources` 照記原本的來源，數值後註明「本機快取，查詢日 YYYY-MM-DD」）；沒有或過期才 WebSearch，查到後寫回（同 key 覆蓋）。格式：
  ```json
  {"<key>": {"value": 0.021, "source": "來源網址或名稱", "fetched": "2026-11-06", "expires": "2027-02-01", "note": "選填"}}
  ```
  | key | 內容 | `expires` |
  |---|---|---|
  | `asset_class:<代號>` | 持股歸類（value 為 asset_class） | 不過期，填 `9999-12-31` |
  | `sec_yield:<代號>` | 債券 ETF 的 30 日 SEC yield | 查詢日 + 1 個月 |
  | `tw_deposit_1y` | 台灣一年期定存利率 | 查詢日 + 1 個月 |
  | `ltcma` | J.P. Morgan LTCMA，value 為 `{asset_class: 報酬}`，`note` 記版本年 | 下一年 11 月 1 日 |
  | `inflation_20y` | 主計總處 CPI 年增率近 20 年平均（未取 max 前） | 下一年 2 月 1 日 |
  | `life_expectancy:<男/女>:<年齡>` | 簡易生命表平均餘命 | 下一年 9 月 1 日 |
  | `labor_rules` | 勞保投保薪資上限、費率等今年規則，value 為物件 | 下一年 1 月 15 日 |

1. **歸類**：把每個持股歸到 `defaults.md` 的 `asset_class`。不確定是什麼標的時用 WebSearch 查。
2. **歷史波動率、相關係數與殖利率**：
   ```
   cd $SKILL/scripts && uv run -q fetch_market.py <所有代號，含退休配置要用的 BND 等> --years 10
   ```
   - 台股自動用 Fugle → yfinance `.TW` → `.TWO`；其他市場用 yfinance → Yahoo chart API
   - Fugle 金鑰依序從環境變數 `FUGLE_API_KEY`、專案目錄的 `.env`（`$SKILL` 往上三層，一行 `FUGLE_API_KEY=...`）讀取；都沒有時會自動跳過 Fugle，不必處理。**不要讀取或印出 `.env` 的內容**
   - 出現在 `failed` 裡的標的：先用 WebSearch 找它的波動率；再找不到就用 `defaults.md` 的類別預設值，並寫進 `notes`
   - `months` 少於 24 的標的，同樣改用類別預設波動率
   - 每個標的另輸出 `div_yield_ttm`（近 12 個月配息殖利率），步驟 3 用來算高登方程式、債券殖利率與 `drag`
3. **前瞻預期報酬**（算法見 `defaults.md`「預期報酬的算法」）：
   - **股票用高登方程式**：實質報酬 = `div_yield_ttm` + 實質股息成長率 1.5% − drag
   - **債券用目前殖利率**：WebSearch 該 ETF 的 30 日 SEC yield，查不到用 `div_yield_ttm`
   - **現金**：WebSearch 台灣一年期定存利率
   - **對照用**：WebSearch 最新一版 J.P. Morgan LTCMA（每年 10 月發布），查不到用 `defaults.md` 的表，填進 `ltcma_return`；`hist_return_annual` 填進 `hist_return`。兩者都**不**用於計算
4. **通膨**：WebSearch 主計總處 CPI 年增率，算近 20 年平均，`inflation = max(該平均, 0.02)`。
5. **平均餘命**：WebSearch 內政部最新簡易生命表中，該性別、該年齡的平均餘命。
6. **勞保／勞退**：WebSearch 確認今年的投保薪資上限與費率是否和 `defaults.md` 一致，有變動就用新值。依出生年決定 `legal_age`。
7. 每一項查到的數值都記到 `sources`（項目、數值、來源網址或名稱）。用到預設值的也要記，並註明「內建預設值」。

## 步驟 3：組輸入並計算

依 `reference/input_schema.md` 寫出 `retirement_input.json`，放在使用者的工作目錄：
- `profile` 列出使用者提供的所有個人資料（性別、出生日期、年齡、退休年齡、生活費、每月投入、持股與現金、退休配置、勞保／勞退或其他退休制度的領取方式與年資、職業等），報告會把它放在最前面的「使用者基本資料」
- 股票類標的設 `gordon: {"div_yield": div_yield_ttm, "real_growth": 0.015}`，不填 `expected_return`；債券、現金的 `expected_return` 填目前殖利率
- 現金放進 `assets`：`symbol: "CASH"`、`asset_class: "tw_cash"`
- 退休配置要用、但目前沒持有的標的，放進 `assets` 並設 `value: 0`
- 美國掛牌的 ETF 依 `defaults.md`「股利預扣稅拖累」設定 `drag`：股票類 = `div_yield_ttm × 0.30`，債券類 = 0；台灣掛牌的設 0
- 勞保、勞退依使用者的選擇設定 `mode`（`monthly` 或 `lump_sum`）。勞保選一次領時，設 `pre2009_years: true` 且 `claim_age` 不可早於退休年齡（一次請領老年給付須年滿 60 歲退職）

```
uv run -q $SKILL/scripts/calc.py retirement_input.json --report retirement_report_YYYYMMDD_raw.md --json retirement_result_YYYYMMDD.json
```

## 步驟 4：開 subagent 產生最終報告

原始報告數字完整但難讀，只留作計算參考；給使用者的最終報告是 subagent 依指引改寫、一般人看得懂的版本（報告內不寫「白話版」，也不寫改寫自原始報告等出處說明）。用 Agent 工具開一個 subagent（`general-purpose`），prompt 給它：
- 指引檔 `$SKILL/reference/final_report_guide.md` 的完整路徑，要它先讀完再動手
- 原始報告（計算底稿）、結構化數據檔 `retirement_result_YYYYMMDD.json`、`retirement_input.json` 的完整路徑，以及 `$SKILL/scripts/calc.py` 的完整路徑（需要底稿第 6 節以外的情境數字時重跑用）
- 輸出路徑：原始報告同目錄的 `retirement_report_YYYYMMDD.md`（原始報告是 `_raw.md`，兩者同日期）

等 subagent 完成後，自己抽查最終報告的關鍵數字（退休金目標、退休時資產、成功率、每月需再多投入、最早退休年齡）與原始報告一致；不一致就請 subagent（SendMessage）修正。

## 步驟 5：回覆使用者

在對話中簡短呈現：
1. **退休金目標**、**預估退休時資產**、**缺口**
2. **每月需再多投入**：確定性與蒙地卡羅 85% 成功率兩個數字
3. **蒙地卡羅成功率**：規劃期、活到 95 歲
4. **最早可以幾歲退休**：用白話說明 `early_retirement` 的三個年齡，例如「想有 85% 的把握錢夠用到 83 歲，58 歲就能退休」「想有 85% 的把握活到 95 歲錢都還夠用，要做到 61 歲」；確定性的年齡（`earliest_deterministic`）只當參考，並說明它假設每年報酬都剛好是平均值，沒算到市場有漲有跌
5. **25 倍法則門檻**（`four_percent_rule`）：目標退休資產、退休時是否已達標或幾歲達標；達標後建議把至少 5～10 年的提領缺口（`liability_matching` 的 `5y`、`10y`）鎖在短債、TIPS 階梯或定存等安全資產（獨立的安全池），其餘留在風險組合，風險組合照使用者的退休配置（含股債）持有；再依 `two_pool_mc` 說明兩池分開運作與每年再平衡哪個成功率較高（見原始報告第 8 節）
6. 最影響結果的 2～3 個假設（通常是報酬率、退休年齡、生活費），以及往哪個方向調整會改變多少。需要的話可以改 JSON 重跑來比較。
7. 兩份報告的完整路徑：**最終報告**（`retirement_report_YYYYMMDD.md`，第一章「一頁看懂」就有結論與改善方案）與**原始報告**（`retirement_report_YYYYMMDD_raw.md`，計算參考：第 0 節是關鍵數字總表，每個數字的算法都在第 10 節「計算過程」）；圖表是 Mermaid，可用 GitHub、Typora 或 VS Code（Markdown Preview Mermaid Support 擴充）檢視

最後附上免責聲明：僅供規劃參考，不構成投資建議；預期報酬為機構推估，非保證。

## 計算方式（向使用者解釋時用）

- **股票實質報酬（高登方程式）** = 起始股息殖利率 + 實質股息成長率。這是伯恩斯坦說的「基本報酬率」，假設估值維持現狀；歷史報酬另含估值膨脹的「投機報酬」，不能期待重演，所以只放在報告當對照
- **債券、現金實質報酬** = 目前殖利率以費雪方程式換成實質
- **投資組合實質報酬** = 加權各資產的實質報酬，再扣除波動拖累 $\sigma_p^2/2$（長期複利成長率會低於平均報酬）
- **目標金額** = $\sum_{t=0}^{T-1} C_t / (1+r_{real})^t$。$C_t$ 是該年生活費扣掉勞保、勞退等固定收入後的金額，期初提領。固定收入不變時就是年金現值公式 × $(1+r)$。
- **退休年數** $T$ = 平均餘命 + 5 年 − 已過的年數（用平均餘命規劃，等於有一半的機率活得更久）
- **25 倍法則（4% 法則，William Bengen）** = 25 ×（年生活費 − 年固定年金收入）+ 固定收入開始請領前的過渡期缺口。它以美國歷史回測 30 年為基礎，與前瞻報酬算出的退休金目標互相對照；退休期超過 30 年時可能不夠
- **負債配合 vs 風險組合**：前 N 年每年須自行負擔的缺口加總（實質、不折現）放獨立的安全池（定存／現金），剩下放風險組合，風險組合照退休配置的股債比例持有
- **蒙地卡羅**：各資產年對數報酬為多變量常態分布，每年再平衡；退休前用目前配置，退休後用退休配置；資產在規劃終點前歸零就算失敗
- **第一版未計入**：所得稅、基金內扣費用、匯率風險
